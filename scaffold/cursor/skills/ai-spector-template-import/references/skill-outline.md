# Generate Skill Outline

Use this outline to write `.ai-spector/packs/.staging/generate-skill.md` during Phase 5 of the template import workflow.

The file you write will become `.cursor/skills/ai-spector-generate-<packname>/SKILL.md` — the skill the agent uses every time a user asks to generate documents with this pack.

**Quality bar:** this skill should be specific enough that an agent who has never seen the template can generate correct, well-structured documents on the first attempt.

---

## File format

The staged file must be a complete, valid Cursor skill file:

```markdown
---
name: ai-spector-generate-<packname>
description: >-
  <one-sentence description — include domain-specific trigger phrases>
paths:
  - "<output root from manifest>/**"
---

# Generate — <packname>

... sections below ...
```

## Section 4 — Wave structure

Describe each wave in human-readable terms. Copy seed IDs from `dag.srs.graph-seeds.json` (which the CLI will have generated by this point — read it from staging or the installed pack dir if already installed).

```markdown
## Wave structure

### Wave 0 — Primary documents (generate first)

| DAG node | Graph seed | Output | Purpose |
|----------|------------|--------|---------|
| `<packname>.srs-template` | `doc.<packname>.srs.template` | `docs/srs/srs.md` | Monolithic SRS |

### Wave 1 — Breakout files (after Wave 0)

| Breakout type | Graph node type | Output pattern | Template |
|---------------|-----------------|----------------|----------|
| `requirement` | `requirement` | `docs/srs/requirements/req-{nn}-{slug}.md` | `req-template.md` |

**Wave 1 per-item workflow (required — one item at a time):**

```
1. npx ai-spector graph query <itemId> --direction both --depth 4 --edges CONTEXT --json
2. Read projectionPaths — these are the only allowed source files
3. Write the breakout file with specific, verifiable content from graph context
4. After all items: batch merge rendersTo edges, then graph validate + index
```

⛔ **Do NOT generate breakout files with a loop or script over knowledge.json.**
Script-generated files pass validate/index but contain boilerplate and no domain context.
See [generate-graph.md §F](../../ai-spector/references/generate-graph.md) for the full rule.

For 10+ items: use sub-agents (one per item or 3–5 per agent). Load context-management.md.
```

Omit Wave 1 section if there are no breakout templates.

## Section 8 — Guardrails

List 3–5 pack-specific guardrails. These should address the most likely mistakes an agent would make with this specific template.

Common guardrails to include:
- Wrong graph seed IDs
- Missing breakout wave
- Wrong output path convention
- Template-specific invariants (e.g. "always include the requirement rationale section")

```markdown
## Guardrails

- Use seed IDs from `dag.srs.graph-seeds.json`, not builtin `doc.srs.*` IDs
- Wave 0 must complete before starting Wave 1 breakout files
- Output to `docs/srs/srs.md` — not `docs/srs/en/srs.md` (no lang subfolder for this pack)
- Every requirement in the output must have a corresponding `FR-xx-yy` node in the graph
- After each wave: `npx ai-spector graph validate && npx ai-spector index`
```
