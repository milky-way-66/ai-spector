# External / hosted prototype — mapping workflow

Use when the prototype **already runs on the server** (another repo, legacy build, or pre-existing deploy) and the web team only needs **`prototype/screen-map.json`**.

No HTML generation, no `prototype sync`, no files in this repo required.

**Web team implementation:** [url-mapping-handover.md](./url-mapping-handover.md)

---

## When to use

| Situation | Use |
|-----------|-----|
| Prototype built elsewhere, hosted at poc.dev.kaopiz.com | **This workflow** |
| Prototype generated in-repo under `prototype/src` or `prototype/dist` | `npx ai-spector prototype manifest` |

---

## Files

| File | Role |
|------|------|
| `docs/basic-design/list-screens.md` | Screen Index — `screenId`, `displayName`, design doc links |
| `prototype/path-map.json` | **Ops fills in** — deploy path per screen (input) |
| `prototype/screen-map.json` | **Output for web team** — generated by CLI |

Only `screen-map.json` is required for the web UI. `path-map.json` is the editable source when paths change.

---

## Agent workflow (confirm before write)

### 1. Gather inputs

Ask the user:

1. **buildMode** — `static` (one HTML file per screen) or `spa` (single app, routes under `dist/…`)
2. **URL layout** — which segments apply?
   - `reviewHost` (required for constructed URLs), e.g. `https://poc.dev.kaopiz.com`
   - `projectId` (optional), e.g. `acme-crm`
   - `deployVersion` (optional), e.g. `1.4`
   - Or **`directReviewUrl: true`** when each screen is a full URL on another host
3. **Hosted paths** — for each Screen Index row:
   - POC path segment(s), e.g. `dist/login` or `login` (flat deploy)
   - Or full URL when `directReviewUrl: true`

Examples:

| Screen | User says | `directReviewUrl` | Example `reviewUrl` |
|--------|-----------|-------------------|---------------------|
| Login on POC (versioned) | `dist/login` | `false` | `https://poc.dev.kaopiz.com/acme-crm/1.4/dist/login` |
| Login on POC (flat) | `login` | `false` | `https://poc.dev.kaopiz.com/login` |
| Login on legacy server | `https://legacy.example.com/app/login` | `true` | same as `prototypePath` |
| Order detail on POC | `dist/orders/demo-001` | `false` | `…/dist/orders/demo-001` |

Paths must match [nginx deploy layout](./nginx-poc.conf) when using the versioned POC — see [url-mapping-handover.md](./url-mapping-handover.md).

### 2. Draft `path-map.json`

**Versioned POC:**

```json
{
  "schemaVersion": 1,
  "buildMode": "spa",
  "hosted": true,
  "reviewHost": "https://poc.dev.kaopiz.com",
  "projectId": "acme-crm",
  "deployVersion": "1.4",
  "defaultScreenId": "login",
  "prototypeBypassAuth": true,
  "buildDest": "dist",
  "screens": {
    "login": { "prototypePath": "dist/login" },
    "order-detail": { "prototypePath": "dist/orders/demo-001" }
  }
}
```

**Flat POC (no project / version):**

```json
{
  "schemaVersion": 1,
  "buildMode": "spa",
  "hosted": true,
  "reviewHost": "https://poc.dev.kaopiz.com",
  "defaultScreenId": "login",
  "screens": {
    "login": { "prototypePath": "login" }
  }
}
```

| Field | Notes |
|-------|-------|
| `hosted: true` | Sets `route_exists: true` (prototype live on server, not verified locally) |
| `screens` keys | Must match Screen Index `screenId` (e.g. `order-detail`) |
| `prototypePath` | No leading slash; no trailing slash on SPA routes |
| `projectId`, `deployVersion` | Optional — omit when URLs have no those segments |

Use the versioned or flat POC templates above when creating `prototype/path-map.json`.

**Direct URL mode** — prototype on another host:

```json
{
  "schemaVersion": 1,
  "hosted": true,
  "directReviewUrl": true,
  "defaultScreenId": "login",
  "screens": {
    "login": { "prototypePath": "https://legacy.example.com/prototypes/login" }
  }
}
```

Each screen's `reviewUrl` will equal `prototypePath` exactly.

### 3. Preview mapping table

Show the user a confirmation table **before writing**:

| screenId | displayName | prototypePath | reviewUrl |
|----------|-------------|---------------|-----------|
| login | Login | dist/login | `https://poc.dev.kaopiz.com/acme-crm/1.4/dist/login` |
| login (flat) | Login | login | `https://poc.dev.kaopiz.com/login` |

Run dry-run:

```bash
npx ai-spector prototype map --dry-run
```

Optional CLI overrides:

```bash
npx ai-spector prototype map --dry-run \
  --review-host https://poc.dev.kaopiz.com \
  --project acme-crm \
  --version 1.4
```

(`--project` and `--version` are optional.)

### 4. User confirms → write

On explicit **yes**:

1. Write `prototype/path-map.json` (if not already saved)
2. Generate screen-map:

```bash
npx ai-spector prototype map --strict
```

`--strict` requires every Screen Index row to have a `prototypePath`.

### 5. User corrections

User edits `prototype/path-map.json` (change paths, add screens), then:

```bash
npx ai-spector prototype map
```

Regenerates `screen-map.json` only — does not touch hosted files on the server.

## Static vs SPA path examples

| buildMode | projectId | deployVersion | prototypePath | Full URL |
|-----------|-----------|---------------|---------------|----------|
| static | acme-crm | 1.4 | `src/login.html` | `…/acme-crm/1.4/src/login.html` |
| static | — | — | `src/home.html` | `…/src/home.html` |
| spa | acme-crm | 1.4 | `dist/login` | `…/acme-crm/1.4/dist/login` |
| spa | — | — | `login` | `…/login` |

Static assets (`src/assets/…`, `dist/assets/…`) are **not** listed in the map — only **screen entry URLs**.

---

## Optional: per-screen `route_exists`

Default with `hosted: true` is `route_exists: true` for all mapped screens.

Override when a screen is not deployed yet:

```json
"checkout": {
  "prototypePath": "dist/checkout",
  "route_exists": false
}
```

Web UI shows “pending” for that row ([handover doc](./url-mapping-handover.md)).

## CLI reference

```bash
npx ai-spector prototype map --dry-run              # preview JSON, no write
npx ai-spector prototype map --strict               # write screen-map.json; all rows required
npx ai-spector prototype map --from other/path-map.json
npx ai-spector prototype map --json                 # JSON output + write
npx ai-spector prototype map --review-host URL      # override host
npx ai-spector prototype map --project SLUG         # optional projectId
npx ai-spector prototype map --version SLUG         # optional deployVersion
npx ai-spector prototype map --direct-review-url    # directReviewUrl mode
```
